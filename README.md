# DataMiners
# AI-сервис выявления нарушений кассовой дисциплины по видео

Проект для Datathon 26 (ForteBank). Сервис принимает видеозапись работы кассира, находит визуально наблюдаемые признаки возможных нарушений и показывает проверяющему тип события, таймкод, кадры-доказательства и ссылку на правило.

Результат работы сервиса является подсказкой для проверки человеком, а не юридическим или дисциплинарным заключением.

## Возможности

- Веб-интерфейс: загрузка видео, статус обработки, вердикт, события с кадрами.
- В footer веб-интерфейса добавлены Telegram-контакты команды.
- Публичный API с ключом (`X-API-Key`) для проверки жюри.
- Полностью локальная работа: без облачных LLM и API, после загрузки весов интернет не нужен.
- Анализ только по видео: без звука, без распознавания и идентификации лиц.

## Как это работает

```
видео → кадры (2 fps) → эмбеддинги CLIP → признаки окон по 3 с
      → классификатор «нарушение / норма» → пики оценок → события
      → кластер события → тип → правило из rules.py
      → (опционально) описание локальной моделью Qwen2-VL-2B
```

1. Из видео берутся кадры с частотой 2 в секунду.
2. Модель CLIP (`open_clip`) превращает каждый кадр в вектор.
3. Векторы объединяются в окна по 6 кадров (3 секунды).
4. Логистическая регрессия оценивает вероятность нарушения в каждом окне.
5. Соседние окна выше порога склеиваются в событие. Таймкод берётся из окна с максимальной оценкой, в доказательства попадают 1-3 кадра рядом с ним.
6. Тип события определяется кластеризацией (KMeans) положительных окон обучающей выборки. Названия кластеров задаются вручную.
7. Если подключён VLM, он добавляет краткое описание того, что видно на кадрах.

Порог обучения подбирается по метрике F2: пропуск нарушения считается хуже ложного срабатывания. При анализе дополнительно действует нижний порог уверенности 25% (`MIN_CONFIDENCE` в `app/detector.py`): события ниже него не возвращаются ни через API, ни на сайте. Для устойчивости к другому ракурсу при обучении используются аугментации (перспектива, поворот, масштаб, зеркало).

## Установка

Для полного проекта рекомендуется Python 3.11. Конвертация текущей разметки проверена на Python 3.14.7, но обучение модели и запуск всего сервиса на Python 3.14 пока не проверялись.

Все команды ниже выполняйте из папки `cashier_ai/`.

```bash
pip install -r requirements.txt
```

Для GPU установите `torch` по инструкции на сайте PyTorch.

### Веса моделей (офлайн)

Скачайте веса заранее, пока есть интернет:

- CLIP: по умолчанию `ViT-B-32` с весами `laion2b_s34b_b79k`. Для офлайн-режима сохраните файл весов локально и укажите путь:
  ```bash
  export CLIP_WEIGHTS=/path/to/open_clip_weights.bin
  ```
- VLM (необязательно): локальная папка с Qwen2-VL-2B-Instruct и переменная `VLM_PATH=/path/to/Qwen2-VL-2B-Instruct`. Для VLM раскомментируйте `transformers`, `accelerate`, `qwen-vl-utils` в `requirements.txt`.

Перед использованием любых весов проверьте, что их лицензия разрешает коммерческое использование.

## Подготовка данных

1. Видео должны лежать в `data/videos/`. В текущем наборе 42 ролика.
2. Исходная таблица находится в `data/open_labels.xlsx` и содержит столбцы `наименование файла`, `таймстемп`, `нарушение / без нарушения`.
3. Если используете другой Excel-файл или другие названия столбцов, измените `SRC`, `COL_VIDEO`, `COL_VIOL` и `COL_TIME` в `convert_labels.py`.
4. Установите зависимости и запустите конвертер:
   ```bash
  python -m pip install -r requirements.txt openpyxl
  python convert_labels.py
   ```

Скрипт создаст `data/labels.csv`, преобразует русские таймкоды в секунды (например, `1минута 8 секунда` станет `68`) и проверит, что видео существует, а таймкод не длиннее ролика. Значение `без нарушения` преобразуется в `0`; наличие таймкода означает метку нарушения `1`.

Текущая таблица успешно преобразована: получено 42 строки, из них 22 с нарушением. При проверке имена видео совпали с файлами, предупреждений о некорректных таймкодах не было.

Формат `labels.csv`:

```
video,violation,timecode_sec
video_001,1,11
video_002,0,
video_003,1,44.2
```

Таймкод указывается в секундах числом, для видео без нарушения поле остаётся пустым.

## Обучение

```bash
python train.py --videos data/videos --labels data/labels.csv --aug 2 --k 5
```

Параметры: `--aug` — число аугментированных копий каждого видео, `--k` — число кластеров типов нарушений.

Скрипт выведет оценку на кросс-валидации (F2, порог, ошибка таймкода) и сохранит `artifacts/model.joblib`. В `artifacts/clusters/cluster_N/` лежат примеры кадров каждого кластера.

### Текущий результат обучения

- В наборе 42 ролика: 22 размечены как содержащие нарушение, 20 — как норма.
- Последний прогон обучения завершился: кросс-валидация показала F2=0.820 при подобранном пороге 0.05; медианная ошибка таймкода — 4.29 секунды.
- В `app/detector.py` установлен минимум уверенности 0.25. Поэтому результат CV выше относится к обученному порогу 0.05 и не является оценкой качества именно при фильтре 25%.
- Эти показатели получены на небольшом наборе и не заменяют проверку на независимых видео с другой камеры.
- Текущие ручные соответствия в `CLUSTER_TO_TYPE`: 0 и 2 → `cash_acceptance_without_client_identification`, 1 → `unattended_cash`, 3 → `unknown`, 4 → `personal_items_on_cashier_desk`. Это интерпретация примеров кластеров, её нужно перепроверять специалистом.

После обучения:

1. Просмотрите примеры кадров в `artifacts/clusters/`.
2. В `app/rules.py` заполните `CLUSTER_TO_TYPE` (номер кластера → тип) и `RULES` (название, описание, нормативный источник).
3. Нормативные ссылки (`document`, `item`) вносите только после ручной проверки на adilet.zan.kz или nationalbank.kz и ставьте `verified=True`. Пока ссылка не подтверждена, сервис выводит пометку о необходимости проверки, а не выдуманный пункт.

В текущем `rules.py` нормативные ссылки для типов приёма наличных без идентификации клиента и личных вещей кассира оставлены с `verified=False`. Не включайте подтверждённый статус, пока не проверены точный пункт и его применимость к вашей организации.

Кэш эмбеддингов находится в `artifacts/cache/`. Он используется при повторном обучении, чтобы не вычислять признаки заново; после завершения экспериментов его можно удалить вручную. Не добавляйте `__pycache__/` и `artifacts/cache/` в GitHub. Для запуска сервиса нужна обученная `artifacts/model.joblib`.

## Запуск сервиса

### Локально в Windows PowerShell

Все команды запускайте из `cashier_ai/` в окружении Python 3.11, где установлены зависимости из `requirements.txt` и `openpyxl`:

```powershell
$env:API_KEY = "ВАШ_СЛУЧАЙНЫЙ_ASCII_КЛЮЧ"
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Установите `API_KEY` до запуска Uvicorn. При смене ключа сервер нужно перезапустить. Используйте латинские буквы и цифры: браузер отправляет ключ в заголовке `X-API-Key`.

Локальная страница: `http://127.0.0.1:8000`. Проверка доступности API: `http://127.0.0.1:8000/health` (возвращает `{"ok":true}`).

### Временный публичный адрес через ngrok

1. Создайте аккаунт ngrok и один раз сохраните authtoken локально командой `ngrok config add-authtoken ВАШ_NGROK_AUTHTOKEN`. Authtoken не является API-ключом проекта; не добавляйте его в GitHub.
1. Оставьте Uvicorn работающим в первом окне PowerShell. Во втором запустите туннель командой `ngrok http 127.0.0.1:8000`.
1. Откройте HTTPS-адрес из строки `Forwarding`, например `https://example.ngrok-free.app`. Для формы жюри указывается только этот базовый адрес, без `/health` и без пути API.

Бесплатный адрес временный и может измениться после перезапуска ngrok. Для доступности извне должны работать компьютер, Uvicorn и ngrok. Не отправляйте через публичный туннель чувствительные видео.

### Docker

Перед запуском подготовьте `artifacts/model.joblib` и веса CLIP. Команды ниже рассчитаны на shell с Docker:

```bash
docker build -t cashier-ai .
docker run -p 8000:8000 -e API_KEY=ваш_ASCII_ключ -v $(pwd)/artifacts:/srv/artifacts -v $(pwd)/weights:/srv/weights cashier-ai
```

Контейнер слушает порт 8000. Не запускайте его одновременно с локальным Uvicorn на том же порту.

## API

Все запросы требуют заголовок `X-API-Key`.

**Загрузка видео**

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
     -H "X-API-Key: ваш_ключ" -F "file=@video_017.mov"
```

Ответ: `{"job_id": "3f2a9c1e"}`

**Получение результата**

```bash
curl http://localhost:8000/api/v1/jobs/3f2a9c1e -H "X-API-Key: ваш_ключ"
```

Статусы: `processing`, `done`, `failed`. Ответ при `done`:

```json
{
  "job_id": "3f2a9c1e",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Название типа нарушения",
      "timecode_sec": 44.2,
      "confidence": 0.91,
      "description": "Что видно на видео и почему это возможное нарушение",
      "rule": {"document": null, "item": null, "note": "..."},
      "evidence_frames": [{"timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..."}]
    }
  ]
}
```

`verdict` принимает значения `violation` и `no_violation`. Для `no_violation` список `violations` пуст.

Загрузка возвращает `job_id`; затем клиент опрашивает `/api/v1/jobs/{job_id}` до статуса `done` или `failed`. Локальный `/health` не требует ключа, оба `/api/v1` маршрута требуют правильный `X-API-Key`. Максимальный размер видео — 300 МБ; файлы принимаются в `.mov` и `.mp4`.

## Ограничения

- Тип нарушения определяется кластеризацией по обучающей выборке. Новые типы, которых не было в данных, получают общий тип «Подозрительное событие».
- Нарушения «по бездействию» (обязательное действие не выполнено) обнаруживаются хуже, чем заметные действия.
- Качество на другом ракурсе камеры ниже, чем на обучающем. Аугментации снижают, но не устраняют эту проблему.
- Сервис не видит данных вне кадра: проводки, журналы и системные сверки недоступны, поэтому выводы ограничены тем, что видно на видео.
- Время обработки зависит от оборудования. На CPU длинные ролики (около 145 с) могут приближаться к лимиту 5 минут. При необходимости снизьте `FPS` в `app/features.py` или используйте GPU.
- Задачи обрабатываются по одной, остальные ждут в очереди. Результаты хранятся в памяти и пропадают при перезапуске сервиса.
