# DataMiners
# AI-сервис выявления нарушений кассовой дисциплины по видео

Проект для Datathon 26 (ForteBank). Сервис принимает видеозапись работы кассира, находит визуально наблюдаемые признаки возможных нарушений и показывает проверяющему тип события, таймкод, кадры-доказательства и ссылку на правило.

Результат работы сервиса является подсказкой для проверки человеком, а не юридическим или дисциплинарным заключением.

## Возможности

- Веб-интерфейс: загрузка видео, статус обработки, вердикт, события с кадрами.
- Публичный API с ключом (`X-API-Key`) для проверки жюри.
- Полностью локальная работа: без облачных LLM и API, после загрузки весов интернет не нужен.
- Анализ только по видео: без звука, без распознавания и идентификации лиц.

## Как это работает

```
видео → кадры (2 fps) → эмбеддинги CLIP → признаки окон по 3 с
      → классификатор «нарушение / норма» → пики оценок → события
      → кластер события → тип → правило из rules.py
      → (опционально) описание локальной моделью Qwen2-VL-2B
```

1. Из видео берутся кадры с частотой 2 в секунду.
2. Модель CLIP (`open_clip`) превращает каждый кадр в вектор.
3. Векторы объединяются в окна по 6 кадров (3 секунды).
4. Логистическая регрессия оценивает вероятность нарушения в каждом окне.
5. Соседние окна выше порога склеиваются в событие. Таймкод берётся из окна с максимальной оценкой, в доказательства попадают 1-3 кадра рядом с ним.
6. Тип события определяется кластеризацией (KMeans) положительных окон обучающей выборки. Названия кластеров задаются вручную.
7. Если подключён VLM, он добавляет краткое описание того, что видно на кадрах.

Порог подбирается по метрике F2: пропуск нарушения считается хуже ложного срабатывания. Для устойчивости к другому ракурсу при обучении используются аугментации (перспектива, поворот, масштаб, зеркало).

## Установка

Требуется Python 3.11.

```bash
pip install -r requirements.txt
```

Для GPU установите `torch` по инструкции на сайте PyTorch.

### Веса моделей (офлайн)

Скачайте веса заранее, пока есть интернет:

- CLIP: по умолчанию `ViT-B-32` с весами `laion2b_s34b_b79k`. Для офлайн-режима сохраните файл весов локально и укажите путь:
  ```bash
  export CLIP_WEIGHTS=/path/to/open_clip_weights.bin
  ```
- VLM (необязательно): локальная папка с Qwen2-VL-2B-Instruct и переменная `VLM_PATH=/path/to/Qwen2-VL-2B-Instruct`. Для VLM раскомментируйте `transformers`, `accelerate`, `qwen-vl-utils` в `requirements.txt`.

Перед использованием любых весов проверьте, что их лицензия разрешает коммерческое использование.

## Подготовка данных

1. Положите видео в `data/videos/`.
2. Положите Excel с разметкой в `data/`.
3. В `convert_labels.py` укажите путь к Excel и названия колонок (`COL_VIDEO`, `COL_VIOL`, `COL_TIME`).
4. Выполните:
   ```bash
   pip install openpyxl
   python convert_labels.py
   ```

Скрипт создаст `data/labels.csv` и предупредит об отсутствующих файлах и неверных таймкодах.

Формат `labels.csv`:

```
video,violation,timecode_sec
video_001,1,11
video_002,0,
video_003,1,44.2
```

Таймкод указывается в секундах числом, для видео без нарушения поле остаётся пустым.

## Обучение

```bash
python train.py --videos data/videos --labels data/labels.csv --aug 2 --k 5
```

Параметры: `--aug` — число аугментированных копий каждого видео, `--k` — число кластеров типов нарушений.

Скрипт выведет оценку на кросс-валидации (F2, порог, ошибка таймкода) и сохранит `artifacts/model.joblib`. В `artifacts/clusters/cluster_N/` лежат примеры кадров каждого кластера.

После обучения:

1. Просмотрите примеры кадров в `artifacts/clusters/`.
2. В `app/rules.py` заполните `CLUSTER_TO_TYPE` (номер кластера → тип) и `RULES` (название, описание, нормативный источник).
3. Нормативные ссылки (`document`, `item`) вносите только после ручной проверки на adilet.zan.kz или nationalbank.kz и ставьте `verified=True`. Пока ссылка не подтверждена, сервис выводит пометку о необходимости проверки, а не выдуманный пункт.

## Запуск сервиса

```bash
API_KEY=ваш_секретный_ключ uvicorn app.api:app --host 0.0.0.0 --port 8000
```

Интерфейс откроется на `http://localhost:8000`: введите ключ, выберите видео и нажмите «Анализировать».

Запуск через Docker:

```bash
docker build -t cashier-ai .
docker run -p 8000:8000 -e API_KEY=ваш_ключ -v $(pwd)/artifacts:/srv/artifacts -v $(pwd)/weights:/srv/weights cashier-ai
```

## API

Все запросы требуют заголовок `X-API-Key`.

**Загрузка видео**

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
     -H "X-API-Key: ваш_ключ" -F "file=@video_017.mov"
```

Ответ: `{"job_id": "3f2a9c1e"}`

**Получение результата**

```bash
curl http://localhost:8000/api/v1/jobs/3f2a9c1e -H "X-API-Key: ваш_ключ"
```

Статусы: `processing`, `done`, `failed`. Ответ при `done`:

```json
{
  "job_id": "3f2a9c1e",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Название типа нарушения",
      "timecode_sec": 44.2,
      "confidence": 0.91,
      "description": "Что видно на видео и почему это возможное нарушение",
      "rule": {"document": null, "item": null, "note": "..."},
      "evidence_frames": [{"timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..."}]
    }
  ]
}
```

`verdict` принимает значения `violation` и `no_violation`. Для `no_violation` список `violations` пуст.

## Ограничения

- Тип нарушения определяется кластеризацией по обучающей выборке. Новые типы, которых не было в данных, получают общий тип «Подозрительное событие».
- Нарушения «по бездействию» (обязательное действие не выполнено) обнаруживаются хуже, чем заметные действия.
- Качество на другом ракурсе камеры ниже, чем на обучающем. Аугментации снижают, но не устраняют эту проблему.
- Сервис не видит данных вне кадра: проводки, журналы и системные сверки недоступны, поэтому выводы ограничены тем, что видно на видео.
- Время обработки зависит от оборудования. На CPU длинные ролики (около 145 с) могут приближаться к лимиту 5 минут. При необходимости снизьте `FPS` в `app/features.py` или используйте GPU.
- Задачи обрабатываются по одной, остальные ждут в очереди. Результаты хранятся в памяти и пропадают при перезапуске сервиса.
