# План: AI-сервис контроля кассовой дисциплины (Datathon 26)

## 1. Архитектура (всё локально)
Видео → выборка кадров 2 fps → CLIP-эмбеддинги (open_clip, MIT) → признаки окон 3 с
→ классификатор «нарушение/норма» (LogReg) → пики → события (таймкод + кадры)
→ кластер события → тип → правило из `rules.py` → (опц.) локальный VLM Qwen2-VL-2B для описания.
FastAPI: `/api/v1/analyze`, `/api/v1/jobs/{id}`, ключ в `X-API-Key`, UI на `/`.

Почему так: 40 роликов слишком мало для обучения детектора с нуля, а готовые эмбеддинги + лёгкий
классификатор дают быстрый, устойчивый базовый уровень и укладываются в 5 минут даже на CPU.

## 2. Этапы
| Время | Что делаем | Результат |
|---|---|---|
| День 1, утро | Смотрим все ролики, выписываем типы нарушений по таймкодам | Таблица «видео → тип» (в разметке типа нет) |
| День 1, день | Исследование НПА РК (adilet.zan.kz, НБРК): кассовые операции, инкассация, охрана кассовых помещений | Список правил с точными пунктами, **verified=True только после ручной проверки** |
| День 1, вечер | `train.py`: кэш эмбеддингов, CV, порог, кластеры | Базовая метрика, `model.joblib` |
| День 2, утро | Названия кластеров → `CLUSTER_TO_TYPE`; разбор ошибок CV | Типы нарушений |
| День 2, день | Устойчивость к ракурсу: аугментации (`--aug`), снять/найти свои видео с другого угла | Рост CV на аугментированных копиях |
| День 2, вечер | Деплой (Docker, публичный URL, HTTPS), прогон через API, замер времени | Работающий сервис + ключ жюри |
| Финал | README, список ограничений, питч (5 мин) | Сдача |

## 3. Критерии → что делаем
- Обнаружение (25): порог по F2 — пропуск хуже ложной тревоги, но ложные тоже штрафуются.
- Локализация (15): таймкод = центр пикового окна; в кадрах первым идёт кадр пика.
- Классификация (15): кластеры + ручное именование; тип `unknown` для новых нарушений.
- Правила (15): никаких выдуманных ссылок; без подтверждённого пункта выводится пометка.
- Устойчивость (10): аугментации перспективы/поворота/зеркала; эмбеддинги CLIP менее чувствительны к ракурсу.
- Продукт/тех (20): очередь на 1 воркер, лимит размера, таймаут VLM, офлайн-режим.

## 4. Риски
- **Лицензии**: Ultralytics YOLO — AGPL, лучше не использовать. Здесь: open_clip (MIT), Qwen2-VL-2B (Apache-2.0). Проверьте лицензию именно тех весов, что берёте.
- **Лица**: не идентифицировать; VLM-промпт запрещает описывать внешность.
- **Нарушения «по бездействию»**: таймкод ставим на момент, где окно максимально отличается от нормы (на усмотрение команды по FAQ).
- **Новый ракурс**: если CV на аугментациях просядет, добавьте детектор людей/зон и признаки на их основе.
- **Время**: 145 с видео ≈ 290 кадров; на CPU эмбеддинги ~1-2 мин. Если медленно — снизить `FPS` до 1.5 или взять GPU.

## 5. Запуск
```bash
pip install -r requirements.txt
# веса CLIP скачать заранее, путь в CLIP_WEIGHTS (офлайн)
python train.py --videos data/videos --labels data/labels.csv --aug 2 --k 5
# посмотреть artifacts/clusters/*, заполнить CLUSTER_TO_TYPE и RULES в app/rules.py
API_KEY=секрет uvicorn app.api:app --host 0.0.0.0 --port 8000
curl -X POST http://localhost:8000/api/v1/analyze -H "X-API-Key: секрет" -F "file=@video.mov"
```
`labels.csv`: `video,violation,timecode_sec` (для норм. видео timecode пуст).
